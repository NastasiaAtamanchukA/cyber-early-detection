# План управления проектом

## Подход

Проект ведется как учебный MVP с проверкой по чек-листу. Управление построено вокруг артефактов, которые можно показать преподавателю: код, сайт, документация, диаграммы, CI/CD, тесты и релиз.

## Вехи

| Веха | Содержание | Ответственный | Критерий готовности |
| --- | --- | --- | --- |
| M1 | Архитектура и каркас | Технический лидер | Структура backend/frontend/ml_service/docker создана |
| M2 | Backend API и БД | Backend | События сохраняются, миграции применяются |
| M3 | ML-сервис | ML | /predict возвращает score |
| M4 | Frontend | Frontend | UI показывает события и алерты |
| M5 | Docker Compose | DevOps | Запуск одной командой |
| M6 | CI/CD и тесты | QA/DevOps | lint/tests/build проходят |
| M7 | Документация и схемы | BA/PM | Все пункты документации закрыты |
| M8 | Релиз | PM | v0.1.0 опубликован, CI зеленый |

## Контроль качества

Качество контролируется через автотесты, статический анализ, ручное тестирование, проверку документации и финальный чек-лист. Перед релизом необходимо выполнить локальные проверки, затем дождаться успешного workflow run в GitHub Actions.
